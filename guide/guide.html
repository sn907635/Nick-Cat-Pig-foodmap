私人美食地圖建置與維護說明

本系統採用「無伺服器純前端架構」，以 Google 試算表作為後台資料庫，前端透過瀏覽器即時解析 CSV 資料並結合 OpenStreetMap 互動地圖渲染。建置完成後，日常新增或修改餐廳僅需編輯試算表，無需更動任何程式碼。

1. 資料維護端
Google 試算表

維護餐廳資料與動態下拉選單，並發布為公開 CSV。

2. 資料解析層
PapaParse 引擎

於使用者瀏覽器端抓取 CSV 並轉換為結構化 JSON 物件。

3. 地圖與介面層
Leaflet.js + Tailwind

渲染多條件篩選器、餐廳卡片清單與互動地圖圖釘。

4. 網站託管層
GitHub Pages

提供免費 HTTPS 靜態網頁空間與跨裝置存取網址。

正式網站網址： https://sn907635.github.io/Nick-Cat-Pig-foodmap/

二、四步驟完整建置與發布流程

可勾選下方各步驟的檢核方塊追蹤設定進度（狀態會自動儲存於目前瀏覽器）。

1

建立 Google 試算表與動態下拉選單

在試算表中建立兩個工作表：「美食清單」（必須放在第一個分頁位置）與「選項維護」。透過「資料驗證」將地區、類型、餐廳分類綁定至「選項維護」對應欄位，實現集中維護選單項目。

2

將試算表發布為 CSV 公開連結

  1. 開啟「私人美食地圖資料庫」試算表，點選左上角 「檔案」 > 「共用」 > 「發布到網路」（注意：繁體中文介面名稱為「共用」而非「分享」）。
  2. 在「連結」分頁中，第一個下拉選單指定選擇 「美食清單」，第二個下拉選單選擇 「逗號分隔值 (.csv)」。
  3. 點擊 「發布」 並確認，複製產生的 https://docs.google.com/spreadsheets/d/e/.../pub?output=csv 網址。
3

將 CSV 網址填入網頁設定區（index.html）

開啟 index.html，找到程式碼下方的 CONFIG 區塊，將複製的 CSV 網址貼入 SHEET_CSV_URL 單引號內並存檔： 

const CONFIG = {
  SHEET_CSV_URL: 'https://docs.google.com/spreadsheets/d/e/你的發布ID/pub?output=csv',
  DEFAULT_CENTER: [24.1512, 120.6815],
  DEFAULT_ZOOM: 13
};
4

上傳至 GitHub 並啟用 GitHub Pages

1. 上傳檔案至儲存庫根目錄：將 index.html（以及本說明檔 guide.html）透過網頁拖曳或以下 Git 指令推送至 main 分支：

git init
git add index.html guide.html
git commit -m "Deploy food map and guide pages"
git branch -M main
git remote add origin https://github.com/sn907635/Nick-Cat-Pig-foodmap.git
git push -u origin main

2. 開啟 Pages 網站託管：前往專案的 Settings > Pages，確認儲存庫為 Public，在 Build and deployment 區塊將 Branch 設為 main、資料夾維持 / (root) 後點擊 Save。等待約 1 至 2 分鐘即可透過正式網址存取。

三、Google 試算表欄位與維護規範

「美食清單」工作表的第一列標題名稱必須與下方表格完全一致，網頁端程式才能正確對應欄位：

欄位名稱 填寫要求 標準格式與範例 系統解析與前端行為說明
地區 必填 台中市北區 由「選項維護」A 欄動態生成下拉選單；前端自動彙整不重複地區作為篩選條件。
名稱 必填 一中街濃厚豚骨拉麵 卡片主標題與地圖圖釘標題；若此欄為空白，程式會自動忽略該列資料。
類型 必填 日式料理 定義為料理菜系（如台式、日式、義式），由「選項維護」B 欄提供下拉選單。
餐廳分類 必填 正餐 定義為用餐情境（如正餐、小吃、咖啡廳、聚餐），由「選項維護」C 欄提供下拉選單。
評分 選填 4.6 數值範圍限制 1.0 至 5.0（支援小數），用於最低評分過濾與高低排序。
經緯度 建議填寫 24.1502, 120.6848 緯度在前、經度在後，以半形逗號分隔。留空時仍會出現在左側清單，但地圖不顯示圖釘。
地圖連結 選填 https://maps.app.goo.gl/... 自訂 Google Maps 分享網址；若留空，網頁會自動以「店名 + 地區」組合搜尋導航連結。
備註 選填 叉燒厚實、尖峰需排隊 可記錄必點菜色、低消或停車資訊，頂部關鍵字搜尋框會同步檢索此欄位。
設計亮點

四、核心設計重點

1. 零營運成本與無 API 計費風險

捨棄需要綁定信用卡與流量計費的 Google Maps JavaScript API，改用開源的 Leaflet.js 搭配 OpenStreetMap 圖資呈現多點位地圖；實際導航則透過外部 URL 喚起使用者手機原生的 Google Maps App，兼顧視覺整合與零成本。

2. 資料與程式完全解耦

餐廳資料與分類選項全數儲存於 Google 試算表。日後無論在電腦或手機上透過試算表 App 新增餐廳、調整評分或擴充「選項維護」分類，網頁端皆會動態同步，完全不需要重新部署 GitHub Pages。

3. 維度分離的雙層分類設計

明確區分「類型（料理菜系，如日式、台式）」與「餐廳分類（用餐型態，如正餐、咖啡廳、聚餐）」，避免資料累積後標籤混亂，讓使用者能精準進行交叉篩選（例如：篩選「台中市北區」＋「日式料理」＋「4.5 分以上」）。

4. 容錯機制與決策輔助

若臨時建檔來不及查詢經緯度或地圖網址，系統具備自動容錯能力（自動產生 Google 搜尋導航連結、清單正常顯示並標註無座標）；此外內建「隨機抽一間」功能，可直接從當前篩選結果中抽選餐廳。

風險與排錯

五、注意事項與常見問題排錯

注意事項 1：Google 試算表更新有 1 至 5 分鐘快取延遲

Google 試算表的「發布到網路」機制在 Google 伺服器端設有快取機制。在試算表新增或修改餐廳後，若立即點擊網頁右上角的「同步資料」尚未看到最新資料，請稍候 1 至 5 分鐘再重新整理即可。

注意事項 2：資料公開性與資訊安全邊界

免費版 GitHub Pages 必須使用 Public 公開儲存庫，且試算表需啟用「發布到網路」，代表任何取得網址或檢視網頁原始碼的人都能讀取該 CSV 內容。請務必確認試算表中僅存放餐廳公開資訊，切勿填入個人住家地址、電話、密碼或任何機密資料。

注意事項 3：鎖定工作表順序與第一列標題名稱

「美食清單」必須維持在試算表底部的第一個分頁位置；同時請勿隨意修改第一列的 8 個欄位標題文字（地區、名稱、類型、餐廳分類、評分、經緯度、地圖連結、備註），否則前端解析器將無法正確對應欄位。

注意事項 4：經緯度格式與取得技巧

經緯度欄位僅接受數字格式（例如 24.1502, 120.6848），在電腦版 Google Maps 地圖紅點上按滑鼠右鍵，點擊第一行的經緯度數字即可自動複製。若貼入中文地址或經緯度順序顛倒，地圖圖釘將無法正確顯示。

注意事項 5：GitHub Pages 顯示 404 Not Found 排錯

若開啟 GitHub Pages 網址出現 404 錯誤，請依序檢查：(1) 主網頁檔名是否為全小寫 index.html；(2) GitHub 專案是否已設為 Public；(3) Settings > Pages 中的 Branch 是否已從 None 切換為 main 並按下 Save。
